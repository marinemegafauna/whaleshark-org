sections:
  - id: today
    heading: How it works today
    body: |
      Every encounter on Sharkbook has an **access** level: public, collaborator-restricted or submitter-private. A Project groups encounters for dashboards, but it is not a security boundary.

      To work on another user's non-public encounters, you send that user a collaboration request and they must accept it. If the submitter has left the team and their account is dormant, nobody can accept; the data is effectively locked.

      Admin access is the only current override. Site-wide admin was withdrawn from users outside MMF after an unrelated user accidentally made a bulk deletion. Wild Me have said they are building a level below admin that can still use all data.
  - id: workarounds
    heading: Workarounds now
    items:
      - Use a shared project account for uploads. Keep one account and one identity, and change the password when someone leaves.
      - Make sure every team member is in your organisation on Sharkbook's user-management page.
      - Send collaboration requests early, in batches, and chase them by email.
      - Post blockers on the Wild Me community forum so they are on the record.
  - id: action-plan
    heading: Action plan · Simon, science advisor · August 2026
    items:
      - Write up the current behaviour plainly on this page.
      - Collect concrete cases from whale shark teams, including the affected encounters and dormant accounts.
      - Take a proposal to Wild Me for a sub-admin “data user” role and organisation-level data access, supported by those cases.
      - Report back here.
